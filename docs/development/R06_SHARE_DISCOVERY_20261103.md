# R06a: Windows 공유 기능 접근 경로 개선 (2026-11-03)

## 목표와 수용 범위

Windows 11 탐색기 직접 대조 R06에서는 파일 선택 메뉴에 공유 진입점이 있었고, flyExplorer 자체 메뉴에는 직접 진입점이 없었다. Windows의 [공식 공유 안내](https://support.microsoft.com/en-gb/windows/experience/connectivity-networking/share-files-in-windows)는 파일 탐색기에서 항목을 선택한 뒤 사용자가 공유 메뉴와 대상을 선택하는 흐름을 설명한다.

이번 **R06a**는 기존 `RevealSelectedInWindowsExplorer(side)`를 재사용하여 선택 메뉴에 **"공유 옵션: Windows 탐색기에서 선택"**을 추가한다. 클릭하면 정확히 현재 선택된 로컬 파일·폴더를 Windows 탐색기에서 선택한 상태로 연다. **사용자가 직접** Windows 탐색기의 공유 메뉴, 대상 및 실제 전송 여부를 선택한다. flyExplorer는 공유 창을 직접 열지 않으며 파일이나 링크를 **외부 전송**하지 않는다.

## 재사용한 안전 경계

- 선택된 실제 파일 시스템 항목만 대상으로 하며 최대 128개와 전체 경로 예산을 넘거나 가상 공급자 항목이면 메뉴가 비활성화된다.
- 파일 작업 실행·충돌 확인창 대기 중에도 비활성화한다.
- 메뉴 지연 클릭 전에 WindowTab, PaneTab, route, 실제 폴더, 논리 항목 식별자와 현재 경로, 선택 개수를 원래 메뉴의 공통 게이트로 다시 확인한다.
- `shellexplorer::reveal`만 호출하고 클립보드, 파일 작업, 공유 계정, OS 설정 및 세션은 변경하지 않는다.
- 기존 압축 위임 메뉴와 추가 옵션 메뉴는 보존한다. Windows 공유 메뉴의 존재와 위치는 시스템 빌드, 공급자와 설치 환경에 따라 달라질 수 있다.
- 상태 메시지는 사용자가 공유 또는 압축 기능을 Windows 탐색기에서 **직접 선택**하도록 안내한다.

## 후속 경계: R06b / R07

- **R06b: 직접 Windows 공유 시트 연동은 미구현.** WinUI 3의 비패키지 창과 Windows 공유 계약 API, 선택 대상 보존, 취소/오류, 외부 전송 여부를 별도 설계·검증한다. 공유 시트 열기와 전송 실행은 서로 다르며 외부 전송 자동화는 사용자 별도 승인 전까지 금지한다.
- **R07: 실행 취소·다시 실행도 미구현.** 재시작 후 기록 보존, 경로 변경·외부 프로그램 수정, 이름 충돌, 휴지통 항목 식별, 이미 실행된 파일 작업의 실패·만료 범위를 먼저 결정해야 한다. 무조건 복사본을 삭제하거나 경로를 되돌리는 자동 기능은 원본 데이터를 손상할 수 있으므로 기존 Shell 작업에 붙이지 않는다.
- R08 ZIP의 Windows 탐색기 위임은 이미 수용된 기능을 재사용하며 자체 ZIP 엔진을 되살리지 않는다.
