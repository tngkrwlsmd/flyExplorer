# PX11 탭별 보기·열 너비 저장 검토

검토 기준: 2026-10-29, `69341079`의 세션/작업공간 소스.
**제안만 작성했으며 제품 정책·코드·세션 형식은 변경하지 않았다.**

## 현재 확인한 동작

| 상태 | 실행 중 소유자 | v4 세션 저장 |
| --- | --- | --- |
| 정렬 | 각 PaneTab | 각 PaneTab의 sort 저장, v1~v3은 패널 정렬 상속 |
| 보기 모드 | WindowTab의 좌/우 패널 각각 | 각 패널의 view 저장 |
| 열 너비 | WindowTab의 좌/우 패널 각각 | 이름 열만 저장. 유형·크기는 현재 세션 형식에 없음 |
| 숨김·확장명·확인란·촘촘한 행 | 각 패널 | 각 패널 플래그 저장 |
| 그룹화 | 경로/탭별 임시 캐시 | 저장하지 않음 |
| F14 명시적 폴더 보기 기억 | 최대 64개 세션 내 경로 | 재시작 후 저장하지 않음 |

근거: `src/base/ui_session.h/.cpp`,
`app/winui/session_coordinator.cpp`, `file_list_state.h`,
`window_workspace_controller.cpp`, `folder_view_controller.h`.
현재 혼합 소유 구조는 의도된 계약이며 결함으로 판정하지 않는다.

## 가치와 비용

이미지 폴더는 아이콘 보기, 문서 폴더는 자세히 보기를 유지하려는 사용자에게
탭별 보기는 유용할 수 있다. 긴 이름과 여러 열을 비교하는 두 탭을 자주
왕복하면 탭별 열 너비도 도움이 된다. 반대로 패널 전체를 일괄 변경하려는
현재 사용 방식에서는 탭 전환 때 보기와 열이 바뀌는 것이 혼란스러울 수 있다.
이 사용 패턴은 실제 사용자 선호를 확인한 사실이 아니라 활용 가능성이다.

직렬화 용량보다 전환·복원·비동기 응답·드래그 소유권을 일관되게 유지하는
비용이 크다. 최대 10 WindowTab × 2패널 × 8 PaneTab = 160개 탭에서,
탭마다 보기 및 이름/유형/크기 너비를 uint32 네 개로 추가하면 2,560바이트다.
이는 기존 패널 필드 유지와 별도 헤더 변경이 없다는 가정의 순수 필드 증분이며,
실제 최종 형식 크기를 확정한 값은 아니다.

## 채택할 경우의 최소 구현안

1. `WindowWorkspaceController`가 탭별 보기/이름/유형/크기 너비 값을 소유하고,
   기존 정렬 전환과 동일한 추가·선택·닫기 경계에서 활성 패널 값을 교환한다.
   MainWindow에 독립적인 저장 상태 기계를 추가하지 않는다.
2. 새 탭은 현재 패널 값을 상속하도록 제안한다. 보기 변경은 현재 PaneTab만
   갱신하며 표시 옵션과 그룹화의 기존 소유권은 유지한다.
3. `SessionCoordinator`가 탭별 값을 캡처/복원하고, UI 독립 저장 형식 v5에
   추가한다. 기존 v1~v4 읽기는 유지하며, 이전 데이터의 탭들은 패널 보기와
   이름 너비를 상속하고 유형/크기는 현재 기본값 180/80을 적용한다.
4. 구버전 앱은 v5를 읽지 못한다. 쓰기 형식 변경, 구버전으로 돌아갈 때의
   동작 및 기존 opt-in 세션 저장 범위를 채택 전에 명시한다. 실제 프로필을
   자동 변환·백업·덮어쓰는 작업은 이 제안에서 수행하지 않는다.
5. F14에서 사용자가 명시적으로 기억한 폴더 보기는 기존처럼 성공한 탐색
   뒤에만 적용한다. 저장된 탭 보기와의 우선순위는 채택할 정책에 함께 넣는다.
6. 열 드래그 시작 시 확보한 WindowTab/PaneTab/route 소유권을 유지하고,
   도중 탭 전환이나 늦은 완료가 다른 탭 너비를 변경하지 않도록 한다.

채택 후 필요한 검증은 v1~v4 상속/v5 왕복, 잘못된 너비·보기 값 거부,
좌/우 및 WindowTab 독립성, 탭 추가/닫기, 복원 중 늦은 이벤트와 활성 드래그
경합에 한정한다. 실제 화면 전후 비교와 정상 종료도 해당 변경 범위에서
별도로 필요하다. 기존 정렬 GUI 전체나 제외한 DPI/접근성 환경을 재실행하지 않는다.

권고: 현재는 혼합 소유 계약을 유지한다. 탭마다 다른 보기를 자주 사용한다는
요구가 확정될 때 이 안을 채택하며, 추가 정책 승인 전에는 구현하지 않는다.
