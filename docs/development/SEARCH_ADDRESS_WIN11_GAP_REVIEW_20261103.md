# 2026-11-03 검색·주소창과 Windows 11 탐색기 잔여 요구사항 검토

## 기준과 확인 수준

- 기준: `flyExplorer/main` `adec7349045331bbb16acbd298c17ad122af69a8`(앞선 폴더 탭 X·붙여넣기 한정 수용 후 문서 커밋).
- 이번 작업은 **최신 main의 C++/XAML·관련 테스트·기존 Windows 실제 대조 기록을 읽은 설계·요구사항 검토**다. 이번에 새로운 Windows GUI, Release 빌드, 실제 기본 탐색기 창 조작이나 픽셀 비교는 실행하지 않았다.
- 2026-10-31 소유 Windows 11 Explorer 실제 비교: [WIN11_LIVE_COMPARISON_20261031.md](WIN11_LIVE_COMPARISON_20261031.md). R01~R05 및 R11·R12와 이번 2026-11-03 폴더 탭 X·붙여넣기 개선은 각 기록의 **한정 수용 완료**다. 이력 표에 남은 최초 '미구현'은 당시 상태일 뿐이다.
- Windows 공식 제품 설명과 검색·주소 입력 변화의 보조 근거:
  - https://support.microsoft.com/ko-kr/windows/experience/fileexplorer/file-explorer-in-windows
  - https://support.microsoft.com/ko-kr/office/foundations-experiences/find-what-you-need-with-microsoft-search
  - https://support.microsoft.com/en-us/servicing/os/windows-11/2026/07/july-28-2026-kb5101681-preview
  - Windows 빌드·계정·Explorer 설정별 변동은 일반화하지 않는다. 2026-07 공식 업데이트에 기재된 인용부호 경로 입력은 현재 `ResolveFriendlyAddress`가 한 쌍을 제거하는 소스 동작과 구분한다. 기본 탐색기의 Windows Search/클라우드 Home과 flyExplorer의 범위 제한된 검색은 동일 제품 기능이 아니다.

| --- | --- | --- | --- |
| **P1-1** | SA01 / 검색 조건 UI 사용성 | `MainWindow.xaml`에는 Windows 인덱스 모드와 내용·정규식 등의 입력이 동시에 표시된다. `validateSearchQuery`는 인덱스에서 허용하지 않는 조합을 거부하고 `OnRunSearch`는 제출 **이후** 설명한다. 이는 확인된 UI 안내 차이이며 기능 실패 확정은 아니다. | 모드 변경 시 사용 불가 조건과 유효 조건이 **실행 전에 명확히 보이도록** 한 화면을 개선한다. 기존 무효 요청 방어·인덱스 자동 우회 금지는 유지. 변경된 검색 UI만 소스/Release/소유 GUI/실제 화면 한정 확인. |

### 직접 대조 R01~R12의 최신 상태를 재분류

- **완료(각 기록의 한정 수용):** R01 선택/폴더 속성 메뉴, R02 배경 분류, R03 8종 보기, R04 단일 선택 바로 가기, R05 Terminal, R11 메뉴 단축키 안내, R12 세부 정보 창, 2026-11-03 폴더 탭 X/붙여넣기 UI.
- **지원하지만 진입 안내 개선 후보:** R08 압축은 **별도 Windows Explorer로 위임**한다. 앱 자체 ZIP 엔진을 복원하는 작업이 아니다.
- **독립 정책·데이터 영향 설계가 먼저:** R06 공유 UI(열기/취소와 실제 외부 전송 별개), R07 Undo/Redo(되돌림 대상·복구 불가·충돌·만료 정의), R09 파일 즐겨찾기(기존 폴더 북마크와 구별), R10 공급자/계정·설치별 메뉴(모든 PC 공통 필수 아님).
- **기존 범위 외 장기 후보:** 사용자 선택 갤러리, 안전한 새 항목 템플릿, PDF 미리보기, 클라우드 동기화 상태, 독립 탭별 보기/열 너비·탭 별도 창. 세션 v4/개인정보 정책 변경을 자동 승인하지 않는다.

## 개발/검증·중단 규칙

1. 첫 개발 단위는 **SA01**. 그 뒤 SA02·SA03를 순서대로 검토하며, 변경의 실제 범위에 따라 소형 한 단위만 수용한다. SA04는 새 재현 근거가 없으면 재시험하지 않는다.
2. 변경 코드와 테스트의 진짜 의존성만 확인한다. UI 변경에는 **동일 소유 fixture의 BEFORE/AFTER 실제 픽셀 비교**와 키보드/포커스, 기존 설정·원본 바이트 보존을 적용한다. 빌드·GUI·픽셀은 새 변경이 생겼을 때 해당 범위만 각각 판정한다.
3. G03 125/150/200% DPI, G04 실제 고대비/Narrator, G05 USB/SMB/UNC, G07 실제 IME 및 공개 배포는 명시적 제외·중단 상태로 유지한다. 일반 개발 지시로 재개하지 않는다.
4. 수용된 변경은 별도 PR을 기다리지 않고 안전한 `main` fast-forward, 개발 현황 갱신, 양 저장소의 임시 브랜치 정리까지 완료한다. 이번 문서 검토는 **기능 코드·Windows 실행 변경 없이 문서만 반영**한다.
