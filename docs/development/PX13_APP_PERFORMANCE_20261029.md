# PX13/G08 전체 앱 로컬 폴더 계측 — 2026-10-29

## 범위와 판정

Windows VM에서 실제 WinUI 앱의 제한된 8,000개 파일 시나리오를 실행했다.
200개 파일로 동일한 실행·스크롤·정렬·종료 절차를 먼저 확인했다.
UI Automation(UIA)에서 결과를 관찰한 지연이며, 최종 픽셀 표시 시간이나
전체 제품 성능 수용은 아니다. 제품 변경 전후 각각 한 번의 탐색 계측이다.
OS 캐시는 통제하지 않았고 통계적 유의성·반복 실행 분포는 확인하지 않았다.

## 재현과 환경

명령: `python tests/winui/benchmark_app_folder.py --items 8000`.
이 명령은 200개 사전 확인 후 8,000개를 실행한다. 기본값은 200개다.

- 중앙 제어 대상: `personal-control-plane`의 `windows-vm`, SYSTEM 서비스가
  제어하고 유일하게 확인한 대화형 세션의 제한된 사용자 작업으로 실행했다.
  개인 PC·RDC·Codex connector는 사용하지 않았다.
- Windows 11 build 26300, x64 Release, 창 960×519 픽셀, 96 DPI.
  배율·고대비·IME·외부 저장장치 설정을 변경하지 않았다.
- 고정 로컬 드라이브의 새 테스트 전용 폴더, 파일명
  `bench-00000.txt`~`bench-07999.txt`, 각 파일 11바이트.
- 각 실행의 APPDATA/LOCALAPPDATA/USERPROFILE/TEMP/TMP를 격리했다.
  기존 설정 6개 존재/해시, 모든 소유 파일 내용, 정상 종료 0을 검사했고
  성공 후 임시 파일과 프로필을 제거했다. 작업 스케줄러의 소유 작업도 제거했다.
- 메모리는 앱 본체만 50ms 간격으로 표본 수집했다. helper/시스템 메모리,
  순간 최대치 누락, UIA 비용, 디스크 캐시 효과는 별도 경계다.

## 확인한 낭비와 최소 수정

`MainWindow::OnNativeResult`의 전체 모델 완성 경로는 페이지마다
`FillFiles`로 부분 목록을 다시 정렬하고 XAML 행을 재생성한 뒤 다음
Shell 페이지를 요청했다. 그 부분 순서는 최종 전체 정렬이 될 수 없다.

메타데이터/상세 캐시 무효화는 유지하면서 다음 페이지를 먼저 요청한다.
실제로 다음 요청을 제출했을 때만 중간 화면 재생성을 생략한다. 마지막
페이지, 일반 수동 탐색, 실패·거부, 제출 실패 및 기존 상한 처리는 유지한다.
20,000개 완전 모델 및 25,000개 메타데이터 색인 제한은 변경하지 않았다.

관측된 8k 정렬 차이는 359.937ms(약 7.64%), 최대 RSS 차이는 -5.797MiB다.
전환 지연은 135.830ms 늘었다. 탐색 표본이므로 인과 효과나 모든 지표의
개선을 주장하지 않는다. 병목 전체가 해결됐다는 판정도 하지 않는다.

## 남은 경계

PX13/G08은 **한 로컬 시나리오의 첫 실제 앱 기준선과 최소 수정 검증 완료**다.
전체 성능 수용은 부분 상태로 남긴다. 8k 정렬은 여전히 4초 이상 걸린다.
여러 회차의 분포·추가 계측에 따른 UI 스레드 입력 지연·최종 픽셀 시점·
메타데이터별 정렬·전체 helper 메모리·다른 제공자/환경은 미검증이다.
기존 helper 169.320ms/1,458.497ms 기록을 이 표와 같은 지표로 사용하지 않는다.
다음 성능 작업을 별도로 선택할 때만 이 경계에서 이어가며, 동일 시나리오를
새 근거 없이 반복하지 않는다.
