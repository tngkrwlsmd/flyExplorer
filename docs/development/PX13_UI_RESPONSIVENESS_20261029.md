# PX13/G08 정렬 중 입력 응답성 — 2026-10-29

## 판정과 범위

8,000개 로컬 파일 정렬 중 **세 회차 모두 사전에 정한 입력 응답성 기준을
통과했다.** 230개 창 메시지 표본의 전송 실패는 0개였으며, 매회 실제
Ctrl+L 입력으로 주소 편집란에 포커스가 이동했다. 이 조건에서 UI가 장시간
막힌다는 근거는 확인하지 못했으므로 제품 C++/XAML은 추가 수정하지 않았다.

정렬 전체는 5.18~5.68초로 여전히 느리다. 이번에는 별도 메시지 계측과
키보드 동작을 추가했고 OS 캐시·호스트 부하를 통제하지 않았으므로 이전
4.354초 표본과 직접 비교해 개선/회귀를 판정하지 않는다. 최종 화면 프레임
표시·모든 입력·전체 제품 성능이 수용됐다는 뜻도 아니다.

## 재현 조건과 사전 기준

명령:

```text
python tests/winui/benchmark_app_folder.py --items 8000 --responsiveness --repetitions 3
```

200개 파일로 같은 실행·메시지·스크롤·정렬·정상 종료 절차를 먼저 확인하고,
새 소유 폴더/프로필에서 8,000개를 세 번 실행한다. 사전 200개는 한 번만
실행하며 회차별 폴더에는 같은 이름과 11바이트 내용의 파일을 만든다.
기존 20,000/25,000 상한, 보기/탭 정책과 사용자 제외 항목은 변경하지 않는다.

- 환경: 승인된 `windows-vm`, Windows 11 build 26300, x64 Release,
  960×519 픽셀, 96 DPI. OS 설정은 변경하지 않았다.
- 정렬 전부터 완료 행을 관찰할 때까지 소유 HWND에만 WM_NULL을 보낸다.
  간격 50ms, 한 번의 제한 시간 1,000ms이며 소유 PID를 매회 재확인한다.
- 사전 목표: 회차당 표본 10개 이상, 전송 실패 0개, 회차별 95백분위
  100ms 이하, 최대 250ms 이하, 정렬 중 Ctrl+L 포커스 관찰 500ms 이하.
- 95백분위는 성공 표본을 정렬한 뒤 `ceil(0.95*n)`번째 값이다.
  실패 표본은 별도 집계하고 최대 지연에는 남기므로 성공으로 오판하지 않는다.
- WM_NULL은 네이티브 메시지 처리 지연이며 XAML 프레임 시간이나 모든
  키보드 입력 지연과 동일하지 않다. Ctrl+L은 별도로 한 번씩 실제 전송하고,
  기존 포커스가 주소란이 아님·정렬 중임·소유 창이 전경임을 먼저 확인한다.
  포커스 완료 시간에는 자동화 도구의 관찰 비용이 포함된다.

세 회차 정렬 시간 중앙값은 5,270.428ms, Ctrl+L 관찰 중앙값은
225.635ms다. 회차별 95백분위는 전체 230개를 합친 95백분위가 아니다.
메모리는 50ms 표본의 앱 본체 RSS이며 helper·시스템 메모리와 순간 최대치는
포함하지 않는다. 200개 사전 확인은 메시지 6개, 최대 10.480ms,
첫 행 1,363.601ms, 정렬 349.179ms였으며 8k 성능 기준에 합산하지 않는다.

모든 실행은 종료 0, 기존 설정 존재/해시 보존, 소유 파일 내용 보존을
확인했다. 성공 후 테스트 폴더/격리 프로필과 소유 스케줄러 작업을 제거했다.
앱·helper를 재빌드하지 않고 이전에 수용한 정확한 런타임을 재사용했다.
