# M2.0 - independent full-window WinUI shell and reusable native command/state boundary

**Product direction:** fully replace app-owned MFC presentation with independent Windows App SDK WinUI 3. This milestone implements a real full-window **shell foundation**, NOT full MFC feature or production parity. The protected original native `main` remains the existing default.

## Actual implemented architecture

- `src/base/explorer_ui_state.h/.cpp` implements `fxfile::explorerui::Model` with no MFC widget, WinRT, user-profile write or in-process Shell enumeration. It owns two pane records with the existing native `shellnav::Session` history/owned snapshots, stable monotonically increasing route IDs, pending worker request IDs, filesystem paths, active tab, active pane and split visibility.
- Native `dispatch(Command)` now owns `ActivatePane`, `SelectTab`, `AddTab`, `CloseTab` and `ToggleSplit`. It rejects an invalid/hidden pane or tab, retains one tab per pane, caps 32 tabs/pane, returns newly issued or retired route IDs and preserves independent right state while hidden.
- `reset()` validates the requested named workspace layout before replacing the model with entirely new route IDs. `markPending()` and `completeRequest()` enforce the per-tab route and latest native worker request token, independently per pane. Worker callbacks still carry native owned snapshots, never COM interface pointers into the XAML UI thread.
- The **actual** independent WinUI `MainWindow.xaml.cpp` and `m19_features.cpp` now use the shared model for real pane/tab commands, request matching and named-workspace restoration rather than maintaining an XAML-only `PaneState` and allocator. Existing two process-isolated Shell helpers, private Job timeout recovery, independent filesystem/namespace watchers and weak-DispatcherQueue cross-thread callbacks are retained. The protected native MFC app is **not yet consuming** this newly reusable class.

## New full-window XAML shell foundation

The existing independent WinUI 3 native `Window`, NOT an MFC XAML Island, now presents a `flyExplorer` application identity header, WinUI 3 badge, testable per-window `System / Light / Dark` theme selector using `RequestedTheme`, a new This PC sidebar route through the private Shell worker, and previously tested real two-pane/tab/list, address/back/forward, named-workspace, opted-in search and footer-status surfaces. Theme choices change the current WinUI window only; theme persistence, physical high-contrast support and full app-owned dialog modernization remain later tasks. The existing native MFC UI and its stored theme settings are untouched.
