# M2.2: WinUI 3 파일 작업 · 한국어 리소스 · 목록 사용성

**개발 범위:** 별도 WinUI 전환 브랜치의 독립 실행형 미리보기. 기본 언어는 Windows 언어와 무관하게 **한국어(ko-KR)**다. 기존 MFC `main`을 교체하거나 전체 기능 동등성을 달성한 제품 릴리스가 아니다.

## 1. 구현한 공통 C++ 및 실제 UI

- `src/base/shell_transfer_core.h/.cpp`: MFC와 WinRT에 독립적인 네이티브 계약. Windows Shell `IFileOperation`을 별도 COM STA 스레드에서 실행하며 **복사, 이동, 휴지통 보내기**를 구별한다. 시작 전에 원본/대상 경로, 최대 32개 선택, 중복 선택, 실제 로컬 고정 드라이브, 직접 및 부모 reparse point, 동일 폴더 이동·자기 자신으로의 폴더 복사를 검사한다. 미지원 경로에서는 작업하지 않는다.
- 이름 충돌 기본값은 **거부**, 기존 대상은 자동 덮어쓰지 않는다. 별도 한국어 확인 창에서 승인한 경우에만 `KeepBoth`로 이름을 바꿔 둘 다 보존하도록 Shell에 요청한다. 확인과 실제 명령 사이의 경쟁(TOCTOU), 인증된 네트워크 공유·외부 Shell 공급자·악의적 동시 경로 변경까지 원자적으로 통제하지는 못한다.
- `IFileOperationProgressSink`가 진행률을 원자 변수에 반영하고 WinUI가 타이머로 표시한다. 취소는 원자 신호와 Shell 콜백에 전달된다. 빠른 작업은 중간 진행률이 보이지 않을 수 있고 임의 시점 취소 스트레스 테스트는 남아 있다.
- **휴지통은 한국어 확인 창의 명시적인 사용자 승인이 필수**다. 자동 테스트는 실제 전역 휴지통을 변경하지 않고 사전 거부 및 GUI 확인 창 취소만 검증했다. 실제 삭제 완료·복원·되돌리기는 별도 승인 시험이 필요하다.
- `m22_transfers.cpp`는 네이티브 스냅샷의 절대 경로로 다중 선택과 반대 창 대상 경로를 만들어 공통 계층에 전달한다. 작업 중 단추를 비활성화하며, 응답에 원래 탭·route·폴더·작업 세대 검사를 적용해 이후 탐색한 다른 창의 UI가 변경되지 않도록 한다.

## 2. 재사용 한국어 WinUI 화면과 목록

- M2.1의 `ShellHeader`·`NavigationSidebar`에 이어 `FileToolbar`·`StatusFooter`도 독립 XAML UserControl로 분리했다. 복사·이동·휴지통·취소·진행 막대와 정렬 컨트롤을 실제 WinUI로 제공한다.
- `Strings/ko-KR/Resources.resw` 및 `DefaultLanguage=ko-KR`을 도입하고 신규 작업 버튼 4개의 `x:Uid`를 연결했다. 나머지 한국어 정적/동적 문자열이 모두 리소스화된 것은 **아니다**. 다른 번역·언어 선택·전체 문자열 이행은 아직 미완료다.
- 양쪽 `ListView`에 다중 선택을 적용하고 폴더 우선, 이름 오름/내림차순, 크기/수정 날짜 내림차순 정렬을 구현했다. Shell 스냅샷을 받은 후 로컬 고정 드라이브의 실제 항목은 별도 Win32 스레드에서 크기와 한국어 날짜를 가져온다. 결과를 표시하기 전 pane route·탭·세대를 검증하고, 재정렬 시 이전 네이티브 파싱 경로로 선택을 복원한다. 원격/가상 폴더의 해당 메타데이터는 공란일 수 있다.
- 두 파일 목록에 앱 자체 오른쪽 클릭 메뉴와 F5 복사, F6 이동, Delete 휴지통, Ctrl+A, Ctrl+C/X/V **앱 내부 전용** 명령을 연결했다. 이는 Windows 전체 클립보드나 설치된 Shell 확장 컨텍스트 메뉴의 기능 동등성을 의미하지 않는다.

## 3. 검증 층위 및 안전 범위

- M2.2 독립 네이티브 Debug와 Release: **각 18/18 PASS**. 로컬 임시 소유 폴더에서 실제 한글 파일 복사·이동·다중 복사·덮어쓰기 없는 충돌 거부/둘 다 유지·시작 전 취소, 잘못된 입력 및 휴지통 동의 계약을 확인했고, 원본 MFC 사용자 설정 6개의 SHA256을 보존했다.
- M1.5~M2.1 및 신규 M2.2 소스 계약 **79/79 PASS**. 초기 소스 검사의 1개 오류는 취소 멤버 이름에 대한 잘못된 테스트 가정을 고친 것이다.
- 집중 실제 WinUI Debug GUI는 **임시 소유 창·폴더에서** 한국어 버튼, 비동기 파일 크기 및 크기 정렬, 한글 다중 선택 복사, 반대 창 이동, 충돌 확인 창의 취소/둘 다 유지, 휴지통 확인 창 취소를 통과했다. 로그 `logs/m22/m22-focus-recovered-multiselect-ko-debug-gui.log`에서 테스트 창 정상 종료와 여섯 사용자 설정 보호도 확인한다.
- **최종 통합 검증 완료:** 동일한 현행 소스로 빌드된 WinUI Debug와 Release의 실제 격리 GUI 모두에서 M1.9 작업 공간/검색, M2.0 테마/분할/네이티브 탭, M2.1 한국어 테마 재시작/한글 파일 작업, M2.2 비동기 파일 크기·정렬/다중 선택 복사/반대 창 이동/이름 충돌 취소·둘 다 유지/휴지통 확인 창 취소를 통과했다. 두 프로세스 모두 정상 종료했고 원본 MFC 사용자 설정 6개의 해시는 유지됐다. 기존 통제된 M1.8 COM 장애·Shell 알림·로컬 루프백 UNC 거부·연속 두 번 시간 초과 복구는 **Debug**에서 별도로 다시 통과했다. 이는 실제 고장 난 외부 Shell 확장이나 인증된 원격 SMB를 검증한 것이 아니다.

## 4. 기능 동등성 작업표

| 영역 | 독립 WinUI의 현재 범위 | 추가 필요 |
|---|---|---|
| 메인 화면·테마·분할 창·탭 | M2.0~M2.1 실기 이력 | 전체 제품 UI·설치 및 되돌리기 |
| 작업 공간·검색·선택형 최근 위치 | M1.9~M2.1 격리 실기 이력 | 고급 검색·전체 설정 마이그레이션 |
| 새 폴더·이름 변경 | M2.1 실기 이력 | 특수 경로·완전한 Shell 연동 |
| 복사·이동·충돌 | M2.2 실제 로컬 소유 폴더 검증 | 원격·외부 Shell·대량 스트레스 |
| 휴지통 | 확인 UI·사전 검증, GUI는 취소 | 실제 삭제·복원·취소 경쟁 조건 |
| 파일 목록 | 다중 선택·기본 정렬·로컬 크기/날짜 | 원격·가상·대규모 목록·추가 열 |
| 키보드·메뉴 | 앱 내부 명령·WinUI 메뉴 구현 | OS 클립보드·Shell 전체 메뉴·드래그 앤 드롭 |
| 한국어 | ko-KR 기본·일부 .resw | 전체 리소스·다른 언어 및 설정 이행 |
| 접근성·장애 | 부분 UIA·기존 제어 장애 시험 | 실제 High Contrast·DPI·Narrator·외부 공급자 |

**제품 동등성 판정이나 기본 MFC main 병합 대상이 아직 아니다.** 기존 실제 사용자 설정 및 원본 스크린샷을 변경하지 않는다.

초기 M2.2 집중 Debug에서는 Ctrl 보조 물리 클릭으로 다중 선택을 재현했다. 그러나 M2.1을 먼저 수행한 통합 테스트에서는 기존 선택과 포커스 상태에 따라 재현되지 않았다. **제품 다중 선택 자체는 단독 GUI에서 통과했지만, 통합 자동화가 불안정한 오류**로 판정하고 테스트 첫 항목을 UIA select()로 단독 선택한 다음 두 번째 항목을 SelectionItem.AddToSelection()으로 추가하도록 수정했다. Debug·Release 통합 실기 및 소스 계약에서 이 재현 방지를 재검증했다. 제품 실행 코드의 편법 수정이나 실제 사용자 폴더 조작은 수행하지 않았다.
