# Windows 11 탐색기 직접 대조와 개발 요구사항 — 2026-10-31

## R01 후속 구현 (2026-10-31)

[선택 항목·현재 폴더 속성 메뉴](R01_PROPERTIES_MENUS_20261031.md)를 추가해
일반 고정 로컬 범위에서 코드25/25·Release·두 대상 창과 실제 화면을 한정 수용했다.
아래 R01 행은 직접 대조 당시의 차이를 보존한 이력이다. 다음 개발 우선순위는 R02다.
드라이브 루트/가상·네트워크 등 기존 helper 제한과 미검증 범위는 유지한다.

## 대조 방식과 환경

공식 문서만 비교한 과거 재점검과 달리 실제 Windows 탐색기와 flyExplorer를 열어
입력·메뉴·원본 화면을 대조했다. 기존 Explorer 창은 조작하지 않고 새로 연
소유 폴더 창만 사용·종료했다. 개인 최근 항목/홈/탐색기 설정을 조사·변경하지 않았다.

- 환경: Windows Professional build **26300.9711**, 설치된 explorer.exe 파일 버전
  **10.0.26100.1441 (WinBuild.160101.0800)**. 관측된 설치 조합이며 모든 Windows
  11 배포판·확장·계정 기능의 공통 동작을 인증하지 않는다.
- 두 프로그램: **Dark, 96 DPI, 1160×640**. OS 테마/DPI 변경 없음.
- 시험 데이터: CompareOwned.txt(22바이트), CompareOwned.md(19바이트), Nested 폴더와
  그 안의 소유 파일. 최초 대조는 동일 폴더를 사용했다. native 화면만 보완한
  후속은 같은 구성의 새 소유 폴더를 재생성했다.
- flyExplorer 빌드 소스 `ee079ed7e75672e58810aa17fc042e37e941c31e`.
  EXE `f9b936b68dd8a664d1cfcec02a98d0970c0e753e3e4ea645ae18950d6ca25599`.
  Helper `3cc8f2e489c9229c8e419199d8b5b63bc512e1c6e503d1943f35984084c08487`.
- 대조 소스8b53d296, native-only 화면 보완 소스5dcdf3b0은 제품 코드가 같음을
  app/winui·src/base diff와 위 실행 파일 해시로 확인했다.
- 최종 문서 정리에서 제품 MainWindow와 Python 검사 두 파일 끝의 불필요한
  빈 줄만 제거했다. 실행 의미가 없는 공백 변경으로 동일 빌드 증거를 재사용한다.

## 이번 직접 대조로 확인하지 않은 범위

Home 개인 기록·전체 Quick access, Gallery 사진 모음, 클라우드 계정/동기화,
모든 검색 조건·제공자, 탭 분리/재시작 저장, 실제 압축/공유/Undo 실행은 미관측이다.
이들은 기존 후보/결정 항목으로 유지하며 이번 비교로 구현 필요가 확정됐다고 쓰지 않는다.
실제 고배율·고대비/Narrator·USB/SMB/UNC 시험은 사용자 제외, 실제 IME는 중단 유지다.
듀얼 패널/두 단계 탭과 v4의 상태 소유권은 보존한다.

## main 반영 및 정리

사용자 지시에 따라 검토·수용한 변경은 `72743bf7d9364b36c48d3873ea865ebf68ed1778`에서
main에 비강제 fast-forward로 직접 반영했다. 새 PR이나 PR merge 명령은 사용하지
않았고, GitHub가 기존 PR #70을 통합 완료로 자동 종료했다.
[#41155449677](https://github.com/tngkrwlsmd/personal-control-plane/actions/runs/41155449677)에서
VM 소스를 해당 main으로 맞추고 clean/앱0·같은 EXE 보존을 확인했다. main과 같은
HEAD임을 확인한 뒤 기존 work 브랜치를 제거했다. 이 완료 문서 갱신은 제품 변경이나
새 빌드/GUI가 아니다. 이후 개발도 정상 변경은 main 직접 반영을 기본으로 한다.
