# M2.1: Korean-default WinUI reusable components and bounded native file commands

Status: owner-approved independent WinUI 3 full UI replacement remains IN PROGRESS. M2.1 is a first reusable-control and native-command slice, not full native MFC feature parity or a production cutover. Default app language is explicitly **Korean (ko-KR)**, not inferred from the Windows UI locale.

## Actual implementation

- The standalone WinUI window now hosts two compiled, reusable XAML UserControls: `ShellHeader` (theme selector/branding) and `NavigationSidebar` (Home/Documents/Downloads/This PC). They delegate real intent via callbacks to the shared `MainWindow` adapter and its M2.0 MFC/WinRT-independent `explorer_ui_state`. The native main remains the original MFC product, not a permanent XAML Island host.
- The user-facing text in these controls, main XAML and current M1.9 workspace/search status flows is in Korean by default. More dialogs, centralized PRI/.resw resources and additional languages are NOT yet complete. A resource localization follow-up is required before production.
- The MFC-free `src/base/preview_preferences` owns a small strict UTF-8-compatible ASCII schema: `schema=1`, `language=ko-KR` and `theme=system/light/dark`. The absent/malformed default is Korean/System. It uses only the dedicated `%LOCALAPPDATA%/flyExplorer.WinUI3Preview/ui-preferences-v1.txt`, never the original MFC `%APPDATA%/fxfile/conf`. It writes a flushed same-directory temp file with atomic replace and serializes off-UI-thread rapid theme updates by increasing revision and a shared private mutex.
- The MFC-/WinRT-free `src/base/file_command_core` provides ONLY two new commands: create a folder inside the currently accepted native filesystem pane folder, and rename an explicitly selected native filesystem entry in that same parent. No overwrite, deletion, copy/move, virtual Shell mutations or unguarded path traversal are intended. `m21_commands.cpp` does the work off the UI thread, disables controls while pending, and suppresses applying a stale async result to an unrelated route, tab or folder. The existing isolated Shell helper and filesystem watcher handle refresh after successful mutations.

## Actual Unicode defect and resolution

During first M2.1 implementation, PowerShell-to-Python source editing without explicit UTF-8 changed three hardcoded runtime `ShellHeader.xaml.cpp::ShowChoice()` strings to ASCII `??` placeholders while the XAML source already contained genuine Hangul. A real owned Debug GUI UIA reading confirmed the actual `ThemeStateText` was literally `??: ???`, not merely console mojibake. Replaced the exact three C++ runtime strings with genuine UTF-8 Korean for System, Light, Dark, and consolidated unconditional `/utf-8` in the project template. The rebuilt real owned Debug UIA read confirmed actual Korean System codepoints. Real Dark/Light/Dark selection persisted privately, a separately launched exact owned WinUI process reloaded Korean Dark, and the physical owned Korean create/rename/non-overwrite GUI passed. Raw Korean inside PowerShell error log output may itself still render as mojibake; compare escaped UIA Unicode text or actual UI, not redirected terminal glyphs.

The real GUI harness also had two test-only defects: it initially tried to locate the invisible outer UserControl wrapper rather than its accessible real child controls, and it called `child_window` on a UIA wrapper rather than a window specification during second-process theme testing. Both were corrected; one exact synthetic orphan child from the failed preliminary test was identified by executable path AND owned fixture argument and terminated. Do not interpret the earlier failed logs as accepted GUI evidence.
