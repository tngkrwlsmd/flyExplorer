# M2.3 단계별 통합: Windows 클립보드, 개인 세션, 실험적 드래그

**상태:** M2.3의 일부 항목 구현·격리 검증. 독립 실행형 WinUI 3 전환 브랜치에서만 작업한다. 기본 언어는 ko-KR이고, 기존 MFC main·사용자 설정·사용자 스크린샷은 보호한다. 이 문서는 **M2.3 전체 완료 또는 실제 제품 전환 승인**을 의미하지 않는다.

## 1. Windows 탐색기 클립보드의 공통 C++ 계약

`src/base/shell_clipboard_core.h/.cpp`는 MFC 및 WinRT에 독립적이다. Win32 `CF_HDROP`의 UTF-16 경로 목록을 최대 32개·65,536바이트로 제한하고, 상대 경로·중복·잘못된 offset·ANSI 페이로드·터미널 null 누락 등 잘못된 입력을 거부한다. Windows 탐색기의 실제 HGLOBAL에는 정렬·패딩이 허용될 수 있어 실제 OS 읽기는 `DragQueryFileW`로 안전하게 해석하되, 테스트용 wire `decode()`는 엄격하게 유지한다. `Preferred DropEffect`에서 정확한 Move만 잘라내기로 해석하고 모호한 값은 Copy로 처리한다. 잘라내기 형식 기록에 실패하면 성공으로 표시하지 않는다.

기존 WinUI `m22_transfers.cpp`에서 Ctrl+C/X/V와 명시적인 Windows 클립보드 컨텍스트 메뉴를 OS의 CF_HDROP 읽기·쓰기와 연결했다. 원본이 여러 디렉터리에 흩어져 있으면 기존 단일 원본 폴더 네이티브 명령 계약을 우회하지 않고 거부한다. 공통 Shell `IFileOperation`은 파일 경로와 로컬 고정 드라이브·연결점 제약을 작업 직전에 다시 검증한다. 이 액션은 **사용자가 해당 명령을 직접 실행했을 때만** 전역 Windows 클립보드를 변경한다. 기존 프로그램이나 실제 사용자 클립보드에 대한 자동화 테스트는 수행하지 않았다. 다른 프로그램 ↔ WinUI 실제 시스템 클립보드 GUI 검증은 여전히 **NOT TESTED**다.

## 2. 명시적으로 저장하는 개인 WinUI 세션 및 재실행 복원

`src/base/preview_session.h/.cpp`는 `%LOCALAPPDATA%/flyExplorer.WinUI3Preview/winui-session-v1.bin`에만 별도 버전/체크섬을 포함한 제한된 바이너리 설정을 기록한다. UI의 **현재 세션 기억** 버튼을 누른 경우에만 원본 작업 창의 폴더·선택된 탭(각 창 최대 8개), 좌우 창 활성 상태·정렬 모드, 창 크기, 분할 비율을 별도의 백그라운드 작업으로 임시 파일에 쓴 뒤 atomic 교체한다. 임의 외부 경로·가상 Shell·UNC·연결점·존재하지 않는 경로·손상된 설정은 거부한다. 작업 중 저장/삭제 경쟁은 별도 단조 증가 revision과 전용 mutex로 제어한다. 명시적인 **기억 삭제**는 해당 WinUI 개인 세션 파일 한 개만 지운다.

기본 인자 없이 실행했을 때만 사용자가 저장해 둔 유효한 개인 세션이 자동 복원된다. 명시적인 시작 폴더·별도 이름 있는 작업 공간 인자는 개인 세션보다 우선한다. 실제 GUI 자동 테스트에서만 격리 폴더 인자와 `FLY_M23_OWNED_SESSION=YES` / `--m23-owned-auto-restore`를 함께 제공하는 테스트 전용 오버라이드가 있다. 이 옵션을 일반 사용자 복원 동작의 통상 경로로 취급해서는 안 된다. UI의 **저장된 세션 복원** 버튼으로 수동 복원도 가능하다.

독립 native Debug·Release 테스트는 실제 한글 폴더의 private 세션 라운드트립·창 크기·정렬·경계·삭제와 OS 클립보드 인코딩/디코딩 및 소유 파일 복사를 함께 검증한다. 소유 GUI Debug에서는 두 개의 서로 다른 폴더를 저장하고 **새로 실행한 정확한 소유 WinUI 프로세스에서 두 창을 자동으로 복원**, 개인 세션 파일 삭제까지 실제로 확인했다. 원본 MFC 설정 6개는 해시 비교만 하며 쓰지 않는다. 실제 다른 PC·별도 Windows 사용자 프로필로 옮기는 설정 이전과 임의 위치 복원은 지원하지 않는다.

## 3. 드래그 앤 드롭의 현황: 동작 검증을 통과하지 않은 실험

현재 `MainWindow.xaml` 및 `m23_drag.cpp`에 양쪽 `ListView`의 `AllowDrop`, `CanDragItems`, `DragItemsStarting`, ListViewItem `DragStarting`, `DragOver`, `Drop`을 연결했다. 동일 창 내부 선택 파일은 프로세스가 생성한 임시 GUID로 식별하고 직접 원본 경로와 현재 창 route를 확인한다. 외부 탐색기에서 전달되는 `StandardDataFormats.StorageItems`는 떨어뜨리기 이벤트가 실제로 발생한 뒤 최대 32개·단일 원본 로컬 폴더로 읽는다. 드롭은 **Copy만 허용**하며 Move를 추측하지 않는다. 최종 변경은 기존 공통 Shell 검증 계층에 전달한다.

**드래그 기능은 미검증이다.** 현재 Debug 빌드와 소스 계약은 통과했지만, 소유 WinUI의 한글 파일을 자동 마우스로 왼쪽에서 오른쪽으로 끌어 복사하려던 물리 GUI 시험 두 종류(기본 ListView drag 및 직접 ListViewItem CanDrag 모두)는 성공하지 못했다. 마우스 좌표는 기록했지만 파일이 생성되지 않았고, 실제 DragStarting/Drop 이벤트가 호출됐는지까지는 확정하지 못했다. 시뮬레이션 한계와 코드 결함을 구분하기 전에는 작동이나 Explorer 간 호환성을 선언하지 않는다. 해당 **실패 진단은 `FLY_M23_OWNED_DRAG_TEST=YES` 옵션에서만 실행**하고, 다른 검증이 이 실패를 숨기지 않도록 일반 통합 시나리오에서는 분리한다. Windows 탐색기에서 WinUI로 외부 드롭 및 WinUI에서 Explorer로 외부 드래그 역시 실제 검증 전이다.

## 4. MFC 기능 동등성 점검 및 다음 완료 게이트

| 영역 | 이번 변경·검증 | 남아 있는 기능 |
|---|---|---|
| Windows 클립보드 | native CF_HDROP/Preferred DropEffect 엄격 검증, WinUI 사용자 명령 연결, 빌드 | 실제 OS 클립보드 실사용·원본 클립보드 보호 격리 GUI |
| 세션 | ko-KR 개인 프로필에 저장/삭제, 두 창 재실행 복원 실제 소유 GUI | 다양한 창 크기·선택 탭과 분할 비율의 실제 픽셀/사용성 검증 |
| 드래그 | 내부·외부 유입 경로 및 공통 Shell 연결 코드 빌드 | **물리 GUI 실패 원인 조사, 외부 WinExplorer 상호 운용 및 outbound 드래그** |
| 파일 목록 | M2.2 크기/수정 날짜·기본 정렬 유지 | 유형별 조절 가능한 실제 컬럼, 시스템 아이콘·썸네일, 대형 목록 |
| 메뉴 | M2.2 앱 고유 한국어 우클릭 명령 유지 | Windows Shell 확장 `IContextMenu` 격리 호스트/권한/크래시 복구 |
| 한국어 | 세션 버튼 3개를 기존 `ko-KR/Resources.resw`에 추가 | 남은 하드코딩 문자열 전면 이전·번역 및 접근성·IME 완전 검증 |
| 휴지통·오류 | 명시적 승인 UI, 불승인/취소 원본 보존 | **실제 Recycle Bin 이동·복원은 아직 NOT TESTED**, 대용량 취소·복구/SMB |
| 제품 통합 | 기존 독립 M1.9~M2.2 기능 계속 유지 | 외부 Shell 확장, 실제 네트워크, 설치/제거/되돌리기, 최종 MFC UI 은퇴 |

**안전 원칙:** 기본 MFC main 코드를 수정하거나 원본 사용자의 탐색기·설정·클립보드·휴지통을 자동으로 조작하지 않는다. 세션과 새 GUI 테스트는 모든 폴더가 정확히 식별된 자체 임시 소유 경로일 때만 실행한다.

## 5. 수용 시험(실제 로그와 일치하도록 최종 업데이트)

최종 빌드·회귀 로그는 `logs/m23`의 무시된 로컬 증거에 기록한다. 정적 계약·네이티브 테스트·컴파일·실제 GUI·외부 호환성 시험의 수준을 혼동하지 않는다. 최종 수용 결과와 실행 파일 해시는 각 구성의 실제 증거 로그를 검사한 다음 기록한다.


### 최종 검증된 부분 수용 결과

- M1.9~M2.3 기능을 함께 검증한 **실제 소유 Debug·Release GUI 모두 PASS**: 독립 한국어 설정, 이전 파일 작업, 개인 세션 명시 저장, 정확한 소유 두 번째 프로세스의 서로 다른 두 창 자동 복원, 개인 세션 삭제. 각 실제 테스트 실행 파일의 정상 종료와 원본 MFC 사용자 설정 6개 보호를 확인했다.
- M2.3 독립 native: Debug **26/26 PASS**, Release **26/26 PASS**. Windows CF_HDROP wire 형식과 한글 합성 경로·엄격 거부·합성 경로의 실제 Shell 복사·개인 세션 제한/라운드트립/삭제를 시험했다. 전역 시스템 클립보드나 실제 사용자의 휴지통을 변경하지 않았다.
- 원본 M1.9~M2.2 및 새 M2.3 정적/계약 회귀: **97/97 PASS**.
- 최신 빌드와 소스가 일치하는 독립 WinUI EXE SHA256: Debug 388432D9BD9DB88B1C4831F4CDE9E7D1D9D670D42BF8047EFF00B9F10ECF522D / Release 28768A9FE1418C81B959D3540E487102AF80688532087BE1916EC0A86801EFD7. 같은 구성의 독립 Shell helper 바이너리 SHA도 상호 일치한다.
- 기존 M1.8의 실제 소유 통제 장애(Debug): COM 지연/작업자 재시작, namespace 변경, 루프백 UNC 접근 실패 후 폴더 보존과 연속 COM 두 번 시간 초과 이후 기존 경로 보존이 모두 PASS. 실제 외부 악성 Shell 확장이나 인증된 SMB 장애 시험은 아니다.
- 각 합격 로그·원본 실패 진단의 SHA256, EXE/helper의 SHA256 및 보호 항목 검증은 Git 무시된 로컬 증거 파일 logs/m23/m23-final-local-evidence-manifest.json에 분리 기록했다. 물리 드래그의 두 GUI 재현은 **실패했고 합격으로 포함하지 않았다**.

따라서 이번 제출은 **M2.3 단계별 체크포인트**이며 M2.3 전체 완료나 제품 전환 승인이 아니다. 드래그 실기, 실제 OS 클립보드 상호 운용, 실제 휴지통 복원, 고급 파일 목록 및 Shell 확장 메뉴와 한국어 전체 리소스화는 후속 작업으로 남는다.
