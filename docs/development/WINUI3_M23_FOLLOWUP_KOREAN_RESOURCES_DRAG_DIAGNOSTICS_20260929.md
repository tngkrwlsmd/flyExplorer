# M2.3 후속: 한국어 리소스·로컬 파일 유형 표시·드래그 단계별 진단

**대상:** 독립 WinUI 3 개발 브랜치. 기존 MFC 메인 화면, 실제 사용자 설정 6개와 사용자 스크린샷은 변경하지 않는다. 이번 작업은 M2.3 후속 부분 구현이며 전체 기능 동등성이나 제품 교체를 의미하지 않는다.

## 구현 및 결함 수정

- `m23_drag.cpp`의 실제 런타임 오류 문구 7개가 과거 잘못된 인코딩으로 `?`가 된 오류를 발견하고 실제 UTF-8 한국어로 모두 복구했다. 회귀 계약은 해당 리터럴이 남아 있으면 실패한다.
- 테스트 소유 환경에 한해 `FLY_M23_OWNED_DRAG_TRACE=YES`에서 목록 끌기 시작, 항목 끌기 시작, 대상 진입, Drop 네 단계의 상태 문구를 구분한다. 일반 사용자 실행 환경에서는 비활성화된다.
- 실제 소유 Debug WinUI에서 자동 마우스 좌표를 기록하며 한 차례 단계별로 재현했다. 끌기를 시작할 때와 대상에 들어갔을 때도 이전 초기 Shell 상태만 반환했고 네 단계 진단 문구 중 어느 것도 관찰되지 않았다. 한글 대상 파일도 생성되지 않았다. 즉 자동화 입력의 실제 WinUI 드래그 이벤트 **도달 여부가 확인되지 않아**, 드래그 구현의 정상/고장을 판정할 근거가 없다. 실제 드래그 성공, 외부 Explorer 드래그/드롭 검증으로 해석하지 않는다. 실패 증거는 `logs/m23/m23-followup-korean-owned-physical-drag-phase-diagnostic.log`.
- 기존 `Strings/ko-KR/Resources.resw`에 현재 XAML 기본 한국어와 일치하는 신규 정적 문자열 리소스 19개를 추가하고 `x:Uid`를 연결했다. 탐색 사이드바, 뒤로/앞으로/상위 폴더, 탭·작업 공간·검색 및 파일 도구 모음을 포함한다. 동적 메시지까지 전부 리소스화한 것은 아니며 다국어 선택은 구현하지 않았다.
- 기존 로컬 고정 드라이브의 비동기 네이티브 메타데이터 스레드에서 파일 확장자 기반 유형(예: `txt 파일`/일반 `파일`/`폴더`)을 추가했다. 외부 Shell 확장, 레지스트리 유형명, 아이콘/썸네일은 읽지 않는다. 해당 유형은 기존 한 줄 세부 목록에 표시하며 너비 조절 가능한 별도 표 컬럼은 아직 없다.

## 합격 조건과 아직 남은 M2.3 단계

- 기존 소스 계약과 신규 UTF-8 문구/리소스 결선/기본 유형 표시 검사 **102/102 통과**. 신규 코드를 포함한 WinUI **Debug·Release 빌드 통과**.
- 실제 합성 소유 GUI에서 두 구성의 M1.9~M2.3 통합 회귀를 실행하여 한국어 파일 유형, 기존 소유 파일 복사·이동·충돌, 개인 세션의 명시 저장/별도 프로세스 두 창 복원/삭제, 정상 종료 및 원본 여섯 설정의 해시 동일성을 확인하는 것이 별도 최종 수용 게이트다. 모든 로그/바이너리 해시는 무시된 `logs/m23` 하위 로컬 증거에 분리한다.
- 실제 Windows 전역 클립보드 GUI 상호 운용, 외부 Explorer 드래그/드롭 및 WinUI에서 Explorer로의 전송, 실제 휴지통의 승인·복원, 전체 한국어 `.resw`·너비 조절 컬럼·시스템 아이콘/썸네일·외부 Shell 확장·인증 SMB·다중 DPI/High Contrast/Narrator/IME·배포·완전한 MFC 기능 동등성은 미완료다.
- 드래그 재현의 다음 수순은 새 자동 마우스 좌표를 반복 생성하는 것이 아니라, 정확히 식별된 **소유 창과 소유 폴더에서 사람의 실제 포인터를 사용하는 단계별 수동 시험**으로 이벤트 도달 여부를 먼저 구분하는 것이다. 원본 사용자 창이나 전역 클립보드·휴지통을 자동화하지 않는다.

기존 부분 체크포인트는 [M2.3 선행 구현 및 실제 검증](WINUI3_M23_CLIPBOARD_SESSION_DRAG_STAGING_20260929.md)에 별도 보존한다.
