## 후속 실제 물리 입력 한정 확인

[41006296625](https://github.com/tngkrwlsmd/personal-control-plane/actions/runs/41006296625)는
UIA Expand 대신 실제 포인터로 부모 메뉴를 hover해 하위 메뉴를 펼쳤다.
첫 실행과 생성 후 재열기 모두 Text→NewMarkdownFileMenuItem ancestry를 확인했고,
기본 이름/편집 포커스, Esc 취소와 추가 파일 미생성, 정상 종료/원본 보존 및
성공 fixture/profile 정리가 PASS다. 같은 제품/EXE를 재사용했으며 새 C++ 수정이나
빌드를 하지 않았다. 실제 입력의 이 조건만 한정 수용하고 이전 FAIL은 보존한다.
자동 Expand의 실패를 실제 사용자 포인터 동작의 제품 결함으로 확대하지 않는다.

이 성공을 같은 메뉴 변형으로 반복하지 않는다. 빈 배경 메뉴의 실제 이름 편집과
전역 클립보드/다른 테마/전체 Explorer 동등성은 여전히 별도 경계다.
당시 재개 예약이 이미 Windows 후속 실행을 맡고 있었으므로 그 슬롯을 덮어쓰지
않았다. 제어 요청은 완료 후 idle로 돌아온 것을 확인했다.
