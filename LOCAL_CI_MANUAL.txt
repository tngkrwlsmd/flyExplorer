flyExplorer local_ci.bat 간단 사용법
================================

PowerShell / Command Prompt에서 프로젝트 루트에서 실행합니다.

현재 활성 개발/CI build 범위
---------------------------
Release-x64-Unicode | x64 한정입니다.

기본/에이전트 CI에서는 아래 명령만 사용합니다.

.\local_ci.bat x64

인자 없는 .\local_ci.bat도 x64와 동일합니다.
Debug-x64, x86 Unicode/Multibyte, x86/release/full profile은 도구에 남겨두지만
사용자가 검증 범위를 다시 넓히라고 명시하기 전에는 실행하지 않습니다.
quick/test/install/policy도 특정 정적/기능/installer/policy 검증을 명시적으로
요청받은 경우에만 별도 evidence로 사용합니다.

.\local_ci.bat
  = 기본 검증. .\local_ci.bat x64와 같습니다.

.\local_ci.bat quick
  = 가장 빠른 정적 Source Invariant + 알려진 회귀 가드 검증을 수행합니다.
  = ModernUI 연결, direct CDialog 현대화 회귀, toolbar/config-tree resource 계약, app/tip/shortcut/go-up DPI icon frame 계약, rename/pattern/config/updater functional-test wiring, installer smoke wiring, 알려진 잘못된 Win32 API 재도입을 함께 검사합니다.

.\local_ci.bat test
  = OS 임시 디렉터리 아래에서 native functional regression을 수행합니다.
  = 실제 product 경로인 xpr::FileSys/FileIo와 SHFileOperation seam을 사용해 copy/move/delete/rename/mkdir, Unicode/공백 파일명, 충돌, 오류, 무결성, cleanup을 검증합니다.
  = batch-rename transform core, fnmatch/FilePath, UTF-8 ConfFileEx persistence, updater version/metadata parser와 conf-dir/startup command quoting contract를 검증합니다.
  = ShellRegistry가 실제 사용하는 context-menu key/command 조립도 quoting과 Unicode 경로를 포함해 검증합니다.
  = production CRC32/MD5 구현은 표준 known-vector로 검증합니다.

.\local_ci.bat install
  = 생성된 NSIS installer와 shell-integration 안전 계약을 검사합니다.
  = 기본값은 실제 설치/제거를 건너뛰어 PASS WITH SKIPS가 됩니다.
  = 관리자 권한의 격리 실행에서 "set FXFILE_INSTALLER_SMOKE=1" 후 실행하면 temp 경로 설치/Runtime Smoke/제거, main/upchecker architecture, Registry/shortcut/startup/profile 비변경, 기존 fxfile process 생존과 sibling sentinel 보존까지 검사합니다.

.\local_ci.bat policy
  = Policy / Readiness / Conformance 검증을 수행합니다.

.\local_ci.bat x64
  = 현재 활성 CI profile입니다.
  = Release-x64-Unicode | x64 Rebuild + Functional Regression + Warning 검사 + 산출물 검사 + Runtime Smoke를 수행합니다.
  = 기존 obj를 재사용하지 않고 소스를 다시 컴파일합니다. 정상 MSBuild 진행 내역은 영구 로그에 저장하지 않고 확정된 build error만 기록합니다.
  = Rebuild 전에 bin 출력 파일 lock을 검사합니다. 이 저장소의 bin에서 실행한 flyExplorer가 있으면 종료한 뒤 다시 실행해야 하며 local CI가 사용자 프로세스를 강제 종료하지는 않습니다.
  = 로그 시작 부분에 현재 Git revision을 기록합니다.
  = x64 executable이 실제로 재빌드되면 bin\x64\build-revision.txt에 해당 Git revision을 기록합니다.
  = preflight/생성 단계에서 실패해 기존 bin\x64\fxfile.exe가 남는 경우, 현재 source revision용으로 재빌드되지 않았다는 WARNING과 기존 artifact revision marker를 출력합니다. 이 경고가 나온 executable은 현재 UI 수정의 runtime evidence로 사용하면 안 됩니다.
  = 평소 개발 후 가장 자주 사용하면 되는 검증입니다.

.\local_ci.bat x86
  = 보존된 호환성 profile입니다. 현재 활성 CI에서는 실행하지 않습니다.
  = 사용자가 범위를 명시적으로 확대한 경우에만 x86 Unicode + x86 Multibyte Rebuild를 수행합니다.

.\local_ci.bat release
  = 보존된 release/package profile입니다. 현재 활성 CI에서는 실행하지 않습니다.
  = 사용자가 범위를 명시적으로 확대한 경우에만 x64 + x86 Release + package/installer 검증을 수행합니다.

.\local_ci.bat full
  = 보존된 전체 검증 profile입니다. 현재 활성 CI에서는 실행하지 않습니다.
  = 사용자가 범위를 명시적으로 확대한 경우에만 Policy + Release/Debug x64 + x86 + package/installer 검증을 수행합니다.

로그
----
모든 실행 로그는 하나의 파일로 저장됩니다.

  logs\local-ci\local-ci.log

실행할 때마다 이전 local CI 로그는 새 로그로 교체됩니다.
MSBuild 진단은 UTF-8로 정규화합니다.
Rebuild 중 일반 MSBuild 진행 출력은 PowerShell/터미널에 표시합니다.
상세 MSBuild 출력은 warning 정책 검사용 임시 파일에서만 사용하며 실행 종료 시 삭제합니다.
local-ci.log에는 실제 MSBuild error 또는 warning 금지 정책이 CI 실패를 만든 경우의 policy error만 기록합니다.

결과
----
PASS
  = 실행한 검증이 모두 통과했습니다.

PASS WITH SKIPS
  = 빌드/정적 검증은 통과했지만 기존 사용자 Registry 보호 또는 installer smoke opt-in 미설정 때문에 일부 실행 검증을 건너뛰었습니다.
  = 건너뛴 Runtime/Installer Smoke는 NOT TESTED입니다.

FAIL
  = 검증 중 하나가 실패했습니다. logs\local-ci\local-ci.log를 확인하세요.

참고
----
policy/full 실행 시 사용하는 Python 가상환경:
  %TEMP%\flyExplorer-policy-venv

이 폴더는 로그가 아니며 삭제해도 다음 실행 시 다시 생성됩니다.

GitHub Actions 저장 공간 관리
--------------------------
hosted Actions는 기한 없이 실행별 사용자 명시 지시가 없는 한 실행 금지입니다. 준비된 workflow는 수동 실행 전용이며 자동 복구하지 않습니다. workflow의 artifact/cache 업로드도 없습니다.
`build/validate_source_invariants.py`는 `actions/upload-artifact`, `actions/cache`,
`actions/upload-pages-artifact`가 hosted workflow에 다시 추가되면 실패합니다.

과거에 남은 중복 release package는 로컬에서 아래처럼 먼저 조회합니다.

  set GH_TOKEN=<GitHub token>
  python build\actions_storage_cleanup.py --retention-days 1

기본값은 DRY RUN이며 아무 것도 삭제하거나 설정을 바꾸지 않습니다.
`flyExplorer-release-package` 중 최신 1개만 보존하고 나머지 삭제 후보/예상 절감 용량을 출력합니다.
출력을 확인한 뒤에만 다음처럼 적용합니다.

  python build\actions_storage_cleanup.py --retention-days 1 --apply

fine-grained token 기준 artifact 삭제에는 repository Actions: write가 필요하고,
retention 변경에는 repository Administration: write가 추가로 필요합니다.
classic PAT은 private repository에 `repo` scope를 사용할 수 있습니다.
계정의 Actions storage 경고는 repository 전체가 아니라 account-level일 수 있으므로,
flyExplorer 정리 후에도 경고가 남으면 Billing/Usage에서 다른 repository를 확인합니다.
